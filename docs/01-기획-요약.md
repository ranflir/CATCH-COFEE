## 1. 프로덕트 개요 (PRD)

| 항목 | 내용 |
|---|---|
| **한 줄 정의** | 저렴한 커피 할인 정보 제공 서비스 |
| **제품 목표** | 주변 카페의 할인·페이백을 손쉽게 파악해 가장 저렴하게 커피 구매, 정보 탐색 시간 절감 |
| **타겟** | 가격 민감 20~30대 직장인·대학생. 메가커피·컴포즈·빽다방 등 저가 브랜드 주 이용, 모바일 친숙 |
| **카테고리** | 라이프스타일 / 일상 |
| **사용자 역할** | User, Admin, Seller |
| **디바이스** | 모바일 앱(iOS/Android), 반응형 웹 |

**핵심 지표:** MAU, WAU, 방문자 수, (결제 도입 후) 조회→결제 전환율, 1인당 평균 절약 금액

**리스크(기획서):** 할인 정보 수집 정확성/실시간성, 카페·핀테크사 제휴 부족, 경쟁 서비스, 정보 오용, 크롤링의 법적/기술적 문제

## 3. 주요 기능 목록 (기능명세서)

| # | 요구사항 | 중요도 | 역할 | 디바이스 |
|---|---|:---:|---|---|
| 1 | 주변 카페 할인 정보 실시간 제공 | 높음 | User | 앱 |
| 2 | 자동 이벤트 정보 수집·요약(크롤링) | 높음 | Admin | 웹 |

| 4 | 사용자 맞춤형 알림 설정 | 중간 | User | 앱 |

### 1. 주변 카페 할인 정보 실시간 제공
- **1.1 위치 기반 카페 검색**: GPS/네트워크 좌표 수집, 반경 설정(50m~5km), 저가 커피점 DB 조회, 목록 정렬(거리/할인/즐겨찾기/알파벳)
- **1.2 지도 기반 표시**: 지도 렌더링(카카오맵/구글맵), 브랜드별 마커, 마커별 핵심 할인 말풍선, 줌/드래그
- **1.3 카페 상세 할인 조회**: 기본정보, 출처별 섹션(자동수집/판매자/사용자제보), 개별 할인 상세(정률·정액/기간/조건), 확인 수 표시, 최적 결제 버튼

### 2. 자동 이벤트 정보 수집·요약
- **2.1 공식 채널 크롤링**: 대상 브랜드 목록 관리, 웹 크롤러(robots.txt 준수), 모바일 앱 API 수집, SNS 수집
- **2.2 파싱 및 DB 저장**: 추출 규칙 정의, NLP 추출, 중복 제거·정규화, 매장별 매핑, 파싱 실패 → 수동 검수 큐
- **2.3 정기 업데이트 스케줄**: 일일 스케줄러(Cron), 실행 로그, 실패 알림(메일/Slack), 수동 트리거

### 3. 최적 결제 방법 추천
- **3.1 결제수단 연동·분석**: 보유 결제수단 저장, 수단별 할인 조회, 최대 할인액 계산 알고리즘, 조건부 할인 검증
- **3.2 추천 표시**: 추천 수단 강조(배지), 예상 할인액(원 단위), 최종 결제액, 수단별 상세 조건

### 4. 사용자 맞춤형 알림
- **4.1 즐겨찾기 카페 알림**: 즐겨찾기 저장, 신규 할인 모니터링, 푸시 전송, 알림 on/off 관리
- **4.2 결제수단 기반 알림**: 수단 선택 알림 설정, 수단별 할인 모니터링, 푸시 전송

### 5. 간편 결제 연동 (V1.1+ 후보)
- **5.1 결제수단 등록·저장**: 추가 폼, 암호화 저장, 목록 관리, 기본 수단 설정
- **5.2 최종 금액 확인·결제 실행**: 결제 화면, 할인 세부 조건, 수단 선택/변경, 결제 API 호출
- **5.3 성공/실패 안내**: 성공 처리·주문 저장, 실패 사유 표시, 영수증 제공

### 6. 사용자 제보로 할인 정보 보완 ⭐ (핵심 차별 기능)
- **6.1 제보 등록**: '할인 정보 추가' 버튼, 단계별 입력 폼, 임시 저장, 등록 확인
- **6.2 입력·첨부**: 할인 내용, 적용 기간, 조건, 정보 출처, **영수증/사진 필수 첨부**, 이미지 압축·업로드
- **6.3 "이 정보 맞아요" 확인**: 버튼 배치, **1인 1회 제한**, 확인 기록, 확인 수 실시간 표시
- **6.4 확인 취소(되돌리기)**: 자동 등록 전까지만 허용, 확인 수 감소
- **6.5 검수·승인 흐름**: 검수 큐, 상세 검수 화면, 자동 검수 규칙(욕설/광고/중복 반려), 상태 관리(대기→검수중→승인/반려/자동등록)
- **6.6 자동 등록 기준**: **서로 다른 3명 확인 시 관리자 승인 없이 자동 등록**, 제보자 알림
- **6.7 사용자 제보 표기**: '사용자 제보' 배지, 상세(제보자/확인수/이력) 링크
- **6.8 판매자/관리자 관리**: 권한 확인, 수정/삭제, 수정·삭제 로깅
- **6.9 제보 상태 조회**: 상태 화면, 실시간 업데이트, 확인 수 표시, 상태별 필터링

### 7. 판매자 직접 할인 등록
- **7.1 직접 등록**: 입력 폼(할인명/정률·정액/적용대상/기간/조건), 검증(할인율 0~100%, 종료>시작), DB 저장(출처='판매자 등록'), 등록 확인
- **7.2 수정·종료**: 수정 화면, 조기 종료, 수정 이력 기록
- **7.3 사용자 노출**: '판매자 등록 할인' 섹션, 상세 표시, 현재 시각 기준 유효성 검증

## 4. 도메인 핵심 비즈니스 규칙 (개발 시 반드시 반영)

1. **할인 출처 3종**: `자동수집(crawl)`, `판매자(seller)`, `사용자제보(report)` — 화면에서 출처별 구분 표시.
2. **제보 확인 규칙**: 1인 1회 확인 / 확인 취소는 자동등록 전까지만 / **3인 확인 시 자동등록**.
3. **자동등록 할인**은 '사용자 제보' 배지 표기 + 판매자·관리자가 수정/삭제 가능.
4. **영수증/사진 필수**(최초 제보).
5. **결제수단 정보는 암호화 저장**(평문 금지).
6. **크롤링은 robots.txt 준수 + 법적 고려** + 실패 시 관리자 알림.
7. **할인 유효성**은 현재 시각 기준 기간·조건 검증 후에만 노출.
