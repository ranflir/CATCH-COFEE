# Cloudflare R2 영수증 업로드 설정 (Catch Coffee)

영수증 presigned 업로드(`POST /api/v1/uploads/receipt-presign`)용 **S3 호환 스토리지** 설정 가이드.  
**R2 권장** — AWS S3 대비 에그레스(다운로드) 비용 없음.

---

## 1. Cloudflare R2 버킷 만들기

1. [Cloudflare Dashboard](https://dash.cloudflare.com) 로그인
2. 왼쪽 **R2 Object Storage** → **Create bucket**
3. 버킷 이름 예: `catch-coffee-receipts` → **Create bucket**

---

## 2. API 토큰(액세스 키) 발급

1. R2 → **Manage R2 API Tokens** (또는 Overview → API Tokens)
2. **Create API token**
   - Permission: **Object Read & Write**
   - Specify bucket: 위에서 만든 버킷만 선택 (권장)
3. 생성 후 **한 번만** 표시되는 값 복사:
   - **Access Key ID** → `AWS_ACCESS_KEY_ID`
   - **Secret Access Key** → `AWS_SECRET_ACCESS_KEY`
4. **Account ID**도 메모 (endpoint URL에 사용)

**S3 API Endpoint** 형식:
```text
https://<ACCOUNT_ID>.r2.cloudflarestorage.com
```

---

## 3. 공개 URL 설정 (제보에 URL 저장 필요)

제보 API는 `receiptImageUrl`에 **공개 접근 가능한 URL**이 필요합니다.

### 방법 A — R2 Public Bucket (간단, MVP)

1. 버킷 → **Settings** → **Public access** → **Allow Access** / **Connect Domain**
2. **R2.dev subdomain** 활성화 → `https://pub-xxxxxxxx.r2.dev` 형태 URL 발급
3. 이 URL을 `S3_PUBLIC_BASE_URL`로 사용 (끝 `/` 없이)

### 방법 B — 커스텀 도메인 (운영 권장)

Cloudflare DNS에 `receipts.yourdomain.com` 등을 R2 버킷에 연결 후  
`S3_PUBLIC_BASE_URL=https://receipts.yourdomain.com`

---

## 4. CORS 설정 (브라우저/앱에서 PUT 업로드)

프론트가 presigned URL로 **브라우저에서 직접 PUT** 하려면 버킷 CORS가 필요합니다.  
API 서버 CORS(`FRONTEND_URL`)와 **별개** — R2 버킷에도 설정해야 합니다.

### 4-1. Cloudflare 대시보드 (권장)

1. [Cloudflare Dashboard](https://dash.cloudflare.com) → **R2 Object Storage**
2. 버킷 **`catch-coffee-receipts`** 클릭
3. **Settings** 탭 → **CORS Policy** → **Edit** (또는 Add CORS policy)
4. 아래 JSON **전체** 붙여넣기 (또는 [`infra/r2-cors-policy.json`](../infra/r2-cors-policy.json) 파일 내용 복사)
5. **Save**

```json
[
  {
    "AllowedOrigins": [
      "http://localhost:3000",
      "http://localhost:3001",
      "http://127.0.0.1:3000",
      "http://127.0.0.1:3001"
    ],
    "AllowedMethods": ["GET", "PUT", "HEAD"],
    "AllowedHeaders": ["*"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3600
  }
]
```

> **프로덕션 프론트 배포 후** `AllowedOrigins`에 실제 도메인 추가  
> (예: `"https://app.catchcoffee.com"`). JSON 배열에 쉼표로 한 줄 추가 후 Save.

### 4-2. Wrangler CLI (선택)

```bash
npm i -g wrangler
wrangler login
wrangler r2 bucket cors set catch-coffee-receipts --file infra/r2-cors-policy.json
```

### 4-3. 동작 확인 (브라우저 PUT)

1. API에서 `receipt-presign` 호출 → `uploadUrl`, `contentType` 확보
2. 브라우저 콘솔 또는 프론트 코드:

```javascript
await fetch(uploadUrl, {
  method: 'PUT',
  headers: { 'Content-Type': 'image/jpeg' },
  body: fileBlob,
});
```

3. CORS 오류 없고 **HTTP 200** → 성공. `publicUrl`로 이미지 열림 확인.

| 증상 | 원인 |
|------|------|
| `No 'Access-Control-Allow-Origin'` | Origin이 `AllowedOrigins`에 없음 → URL·포트 확인 |
| preflight 403 | `AllowedMethods`에 `PUT` 없음 |
| PUT 403 (CORS 아님) | presign 만료(5분) 또는 Content-Type 불일치 |

## 5. 환경변수

### 로컬 (프로젝트 루트 `.env`)

```env
AWS_REGION=auto
S3_ENDPOINT=https://<ACCOUNT_ID>.r2.cloudflarestorage.com
AWS_ACCESS_KEY_ID=<R2 Access Key ID>
AWS_SECRET_ACCESS_KEY=<R2 Secret Access Key>
S3_BUCKET=catch-coffee-receipts
S3_PUBLIC_BASE_URL=https://pub-xxxxxxxx.r2.dev
```

### Railway (프로덕션 API)

프로젝트 폴더에서 (Railway CLI 로그인 후):

```bash
railway variables --service "@catch-coffee/api" \
  --set "AWS_REGION=auto" \
  --set "S3_ENDPOINT=https://<ACCOUNT_ID>.r2.cloudflarestorage.com" \
  --set "AWS_ACCESS_KEY_ID=<R2 Access Key ID>" \
  --set "AWS_SECRET_ACCESS_KEY=<R2 Secret Access Key>" \
  --set "S3_BUCKET=catch-coffee-receipts" \
  --set "S3_PUBLIC_BASE_URL=https://pub-xxxxxxxx.r2.dev"
```

> `<...>` 는 실제 값으로 바꿉니다. Secret은 GitHub/채팅에 올리지 마세요.

설정 후 main 푸시 또는 `railway up --service "@catch-coffee/api"` 로 재배포.

## 6. AWS S3를 쓸 경우 (대안)

R2 대신 AWS S3를 쓰면:

```env
AWS_REGION=ap-northeast-2
# S3_ENDPOINT 는 비움
AWS_ACCESS_KEY_ID=<IAM access key>
AWS_SECRET_ACCESS_KEY=<IAM secret>
S3_BUCKET=catch-coffee-receipts
# 버킷 public read 또는 CloudFront URL
S3_PUBLIC_BASE_URL=https://catch-coffee-receipts.s3.ap-northeast-2.amazonaws.com
```

버킷 정책·CORS·Block Public Access 설정을 AWS 콘솔에서 별도 구성해야 합니다.

## 7. 동작 확인

### 7-1. 로그인 후 presign 발급

```bash
# 1) 회원가입/로그인으로 accessToken 확보
curl -s -X POST http://localhost:3000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"you@example.com","password":"yourpassword"}'

# 2) presign (Bearer 토큰 교체)
curl -s -X POST http://localhost:3000/api/v1/uploads/receipt-presign \
  -H "Authorization: Bearer <accessToken>" \
  -H "Content-Type: application/json" \
  -d '{"contentType":"image/jpeg"}'
```

응답 예:
```json
{
  "success": true,
  "data": {
    "uploadUrl": "https://...",
    "objectKey": "receipts/<userId>/<uuid>.jpg",
    "publicUrl": "https://pub-xxx.r2.dev/receipts/...",
    "expiresIn": 300
  }
}
```

### 7-2. 클라이언트 PUT 업로드

```bash
curl -X PUT "<uploadUrl>" \
  -H "Content-Type: image/jpeg" \
  --data-binary @receipt.jpg
```

### 7-3. publicUrl 접근

브라우저에서 `publicUrl` 열어 이미지가 보이면 성공.

## 8. 트러블슈팅

| 증상 | 원인 | 해결 |
|------|------|------|
| `S3_BUCKET` 에러 | env 미설정 | `.env` / Railway 변수 확인 |
| `S3_PUBLIC_BASE_URL 환경변수가 필요` | R2인데 public URL 없음 | §3 Public Bucket 또는 커스텀 도메인 |
| PUT 403 | CORS 또는 presign 만료 | §4 CORS, 5분 내 업로드 |
| PUT 후 publicUrl 404 | Public access 미설정 | R2 Public Bucket / 정책 확인 |
| Credentials 에러 | 키 오타·권한 부족 | R2 API token Object Read & Write |
