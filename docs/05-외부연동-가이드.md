# 05. 외부 API 탐색 + 연동 가이드

> 서비스 구현에 필요한 **외부 API**를 기능별로 찾고, 발급·연동 방법을 정리. 모든 키는 `.env`(하드코딩 금지).

## 요약 — 필요한 외부 연동

| # | 용도 | 1순위(권장) | 대안 | V1.0 필수? |
|---|---|---|---|---|
| 1 | 지도 렌더링 | **Kakao Maps SDK** | Naver Maps, Google Maps | ✅ |
| 2 | 장소(카페) 검색·좌표 | **Kakao Local REST API** | Naver Search Local, Google Places | ✅ |
| 3 | 푸시 알림 | **FCM** (Expo Push) | APNs 직접 | ✅(기능4) |
| 4 | 이미지 저장(영수증) | **Cloudflare R2 / AWS S3** | Supabase Storage | ✅(기능6) |
| 5 | 결제(PG) | **PortOne(아임포트)** 또는 **Toss Payments** | 네이버페이/카카오페이 직접 | ❌ V1.1 |
| 6 | 크롤링 | 자체(Playwright/Cheerio) + (선택)SNS API | — | △ PoC |
| 7 | NLP/요약 파싱 | **Claude API**(선택) | 규칙 기반 | ❌ 후순위 |
| 8 | OCR(영수증 검증) | Naver CLOVA OCR / Google Vision | — | ❌ 후순위 |
| 9 | 운영 알림(크롤 실패) | **Slack Incoming Webhook** | 이메일(SMTP) | △ |

## 1. 지도 + 장소 검색 — Kakao (권장)

국내 카페 데이터·정확도·무료 한도에서 국내 서비스에 최적. 카페 카테고리 코드 `CE7` 지원.

- **발급**: [Kakao Developers](https://developers.kakao.com) → 애플리케이션 추가 → JavaScript 키(지도 SDK용) + REST API 키(서버 검색용) 발급. 플랫폼에 도메인/번들ID 등록.
- **장소 검색(서버)**: 카테고리/키워드 + 반경 검색
  ```bash
  # 카테고리(카페 CE7) + 좌표 + 반경(m, 최대 20000)
  curl "https://dapi.kakao.com/v2/local/search/category.json?category_group_code=CE7&x=127.027&y=37.497&radius=1000&sort=distance" \
    -H "Authorization: KakaoAK ${KAKAO_REST_API_KEY}"
  ```
  → `documents[]`(place_name, x/y 좌표, distance, address) 로 `cafes` 시드/검증.
- **지도 SDK(웹)**: `<script src="//dapi.kakao.com/v2/maps/sdk.js?appkey=KEY">` → 마커/말풍선.
- **모바일(Expo)**: WebView 임베드 또는 `react-native-kakao-map` 류 사용.
- **`.env`**: `KAKAO_REST_API_KEY=`, `KAKAO_JS_KEY=`
- **연동 위치**: `apps/api`(검색·좌표 캐싱), `apps/web`/`apps/mobile`(렌더링).
- **대안 트레이드오프**: Google Places는 글로벌·문서 우수하나 국내 소형 카페 커버리지/한글 정확도 ↓ + 과금 발생 빠름. Naver는 국내 강하나 지도/검색 키 정책 분리.

## 2. 푸시 알림 — FCM (Expo Notifications)

- **발급**: Firebase 프로젝트 생성 → Cloud Messaging → 서버키(또는 서비스 계정 JSON). iOS는 APNs 키 등록.
- **Expo**: `expo-notifications`로 디바이스 토큰 획득 → `POST /me/devices`로 서버 저장 → 서버가 신규 할인 감지 시 Expo Push API/FCM로 발송.
  ```bash
  curl -X POST https://exp.host/--/api/v2/push/send \
    -H "Content-Type: application/json" \
    -d '{"to":"ExponentPushToken[..]","title":"새 할인","body":"메가커피 10% 할인"}'
  ```
- **`.env`**: `FCM_SERVICE_ACCOUNT=`(또는 경로), `EXPO_ACCESS_TOKEN=`
- **연동 위치**: `apps/api` 알림 모듈 + 알림 잡 큐(BullMQ).

## 3. 이미지 저장 — S3 호환 (R2 권장)

영수증/할인 사진. **presigned URL** 방식으로 클라이언트 직접 업로드(서버 부하↓).

- **발급**: Cloudflare R2(에그레스 무료) 또는 AWS S3 버킷 + IAM 키.
- **흐름**: 클라 → `POST /api/v1/uploads/receipt-presign` → presigned PUT URL → 클라 PUT → `publicUrl`을 제보에 저장.
- **`.env`**: `S3_BUCKET`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, R2 시 `S3_ENDPOINT` + `S3_PUBLIC_BASE_URL`
- **상세 설정**: [`docs/06-S3-R2-설정.md`](06-S3-R2-설정.md)
- 이미지 압축은 클라(Expo) 또는 서버 `sharp`(WARA에 이미 sharp allowBuild).

## 4. 결제(PG) — V1.1, PortOne/Toss 권장

> ⚠️ **네이버페이·카카오페이 직접 연동은 사업자 등록 + 가맹 심사 + 계약**이 필요. 개인/MVP 단계에선 불가에 가깝다. → **집계 PG**로 우회하거나 V1.0은 *추천까지만*.

- **PortOne(구 아임포트)**: 하나의 SDK로 카카오페이/네이버페이/카드 등 다중 PG 연동. 테스트 상점으로 개발 가능.
- **Toss Payments**: 문서·DX 우수, 테스트 키 제공. 위젯/결제창 + 서버 승인(`/confirm`) 2단계.
  ```bash
  # Toss 결제 승인(서버) 예시
  curl -X POST https://api.tosspayments.com/v1/payments/confirm \
    -H "Authorization: Basic $(echo -n ${TOSS_SECRET_KEY}: | base64)" \
    -H "Content-Type: application/json" \
    -d '{"paymentKey":"..","orderId":"..","amount":4500}'
  ```
- **`.env`**: `TOSS_CLIENT_KEY=`, `TOSS_SECRET_KEY=` (또는 `PORTONE_*`)
- **연동 위치**: `apps/api` payments 모듈 + 웹훅 수신 엔드포인트(결제 상태 동기화).
- **V1.0 결정(권장)**: 기능명세 중요도=낮음 + 계약 의존 → **결제 실행은 V1.1로 연기**, V1.0은 결제수단 등록 + 추천 표시까지.

## 5. 크롤링 — 자체 구현 (기능 2, PoC 권장)

- **정적 페이지**: `cheerio` + `fetch`. **동적/JS 렌더링**: `playwright`.
- **대상**: 메가커피·컴포즈·빽다방 공식 이벤트 페이지. **robots.txt 준수 + 약관 확인 필수**(기획서 리스크).
- **SNS**: 인스타그램은 비공식 스크래핑 금지 강함 → **Instagram Graph API**(비즈니스 계정·앱 심사 필요)만 합법. V1.0 제외 권장.
- **운영**: BullMQ 잡 + Cron(일일). 실행 로그/실패 알림(→ §9 Slack).
- **법적 안전책**: V1.0은 **판매자 등록 + 사용자 제보**로 데이터 부트스트랩, 크롤링은 1개 브랜드 PoC로 한정(법무 검토 후 확대).

## 6. (선택) NLP/요약 — Claude API

크롤링된 비정형 텍스트에서 할인명/율/기간/조건 추출. 규칙 기반으로 시작하고, 정확도 부족 시 LLM 보강.

- **발급/사용**: Anthropic API 키. 추출은 **structured output(tool use)**로 JSON 강제. (상세는 저장소의 `claude-api` 스킬 참조)
- **`.env`**: `ANTHROPIC_API_KEY=`
- **주의**: 비용·환각. 추출 결과는 검수 큐를 거치게.

## 7. (선택) OCR — 영수증 검증

CLOVA OCR(국내 영수증 특화) 또는 Google Vision. V1.0은 첨부 강제만, 검증은 후순위.

## 8. 운영 알림 — Slack Webhook

크롤링 실패/검수 큐 적체 알림(기능 2.3.3).
```bash
curl -X POST -H 'Content-type: application/json' \
  --data '{"text":"크롤링 실패: 메가커피 (2건)"}' ${SLACK_WEBHOOK_URL}
```
`.env`: `SLACK_WEBHOOK_URL=`

## 연동 우선순위 (구현 순서 제안)

1. **Kakao Local + 지도** → 탐색이 가장 먼저 동작해야 데모 가능.
2. **S3(R2) presigned 업로드** → 제보(핵심 차별점) 가능.
3. **FCM/Expo 푸시** → 즐겨찾기 알림.
4. (V1.1) **Toss/PortOne 결제**.
5. (PoC) **크롤링 1개 브랜드** → 필요 시 Claude 파싱.
